# 자세히 RAG 구현 및 검증

빠른 모드 `/v1/chat`를 유지하고 `/v1/chat/detailed`를 추가했습니다. 테스트 UI의 답변 방식에서 빠르게/자세히를 선택할 수 있으며 기본값은 빠르게입니다.

설명·비교 질문은 대화 문맥을 포함한 구조화 해석 → 최대 3개 병렬 검색 → 후보 최대 24개 중 관련도·근거 충족 여부 점검 → 필요할 때 보완 검색 1회 → 최대 8개 근거로 답변 순서로 처리합니다. 목록·일반 대화는 확장 검색 없이 처리합니다. 해석·재정렬·답변 합계 최대 3회 LLM 호출이며 재귀 조사 루프는 없습니다.

모든 검색에 기존 권한, 메타데이터 필터, 이전 결과 범위를 적용합니다. 재정렬 오류·시간 초과 시 최초 결과로 돌아가고 한계를 표시합니다. 서비스 장애를 근거 부족으로 간주해 반복 검색하지 않습니다. 임베딩 호환성이 검증되지 않은 소스는 기존 키워드 검색을 유지합니다.

기본 처리 제한 45초, 재정렬 제한 8초입니다. 이 값은 응답 속도 보장이 아닙니다. 스트리밍 없이 완료 후 응답하므로 설명 질문은 빠른 모드보다 기다림이 늘 수 있습니다.

## 공통 근거 상태 계약
빠르게/자세히 모두 `GroundedAnswer(answer, missing, evidence_ids, evidence_status)`을 반환합니다.
- sufficient (충분): 확인된 설명과 유효한 인용을 반환합니다.
- partial (부분적): 확인된 관련 내용은 인용해 보존하고, `missing`의 질문별 부족한 내용을 덧붙입니다. 일반적인 관련 내용과 질문의 직접적인 답을 혼동하지 않습니다.
- none (없음): 사실 설명 `answer`는 비어 있어야 하며, `missing`에 이번 질문에서 확인할 수 없는 정보를 설명합니다. 관련 없는 참고자료를 답변 근거로 표시하지 않습니다.

고정 부족 문구로 덮어쓰지 않습니다. partial/none은 제한된 정상 결과이며, 충분·부분적 설명의 인용 검증은 유지합니다. 잘못된 인용이나 잘못된 구조는 부족 판정으로 위장하지 않습니다. 서로 다른 검색 근거에서 두 모드의 판단·문장이 항상 같다는 보장은 없습니다.

근거 ID는 구조화 필드로 받아 서버에서 표시하고 실제 검색 자료와 대조합니다. 본문 인용 누락 때문에 유효한 설명이 소실되지 않게 하며, 존재하지 않는 근거 ID는 여전히 차단합니다.
