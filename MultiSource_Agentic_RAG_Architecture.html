02 / Semantic calls

LLM은 한 번이 아니라 네 번 쓰인다

단순 조회는 routing → planner → judge → answer 순서로 4회다. 추가 검색이 필요하면 Judge가 다음 ToolAction을 내고 검색 라운드마다 Judge 호출이 늘어난다.

LLM 01 · system prompt

Routing — IntentDecision

요청당 1회
질문과 제한된 대화 메모리를 하나의 IntentDecision으로 구조화하세요.

의미 책임:
- intent: 질문의 목적을 짧게 요약합니다.
- source_requests: 답변에 꼭 필요한 최소 논리 소스와 각 소스용 의미 검색어를 지정합니다.
- entities: 질문에 명시되거나 안전한 메모리에 있는 의미 엔터티만 지정합니다.
- time_scope: 허용된 시간 범위 enum 중 하나를 지정합니다.
- event_reference: none 또는 previous_event입니다.
- calendar_detail_required: Calendar 상세/첨부 확장이 필요한지 나타냅니다.

서버가 소유하는 ID, 물리 index/alias, filter, ACL, 도구 이름, 쿼리 DSL을 출력하지 마세요.

03 / Responsibility

LLM이 판단하고 Python이 경계를 지킨다

Python 안전장치는 의미를 추론하지 않는다. 모델이 낸 구조화 결정을 허용된 범위 안에서만 실행하고, 사용자 격리와 결과 형식을 검증한다.

Semantic owner

LLM의 책임

질문과 근거의 의미를 해석하는 일

  • 질문의 의도와 필요한 논리 소스 해석
  • 각 소스에서 검색할 의미 쿼리 작성
  • 다음에 실행할 허용 도구 하나 선택
  • 현재 근거의 충분성과 누락 정보 판정
  • 검색 근거만 사용해 한국어 인용 답변 생성
Execution owner

Python의 책임

모델 결정을 안전하고 제한적으로 실행하는 일

  • Pydantic 구조와 길이·enum 검증
  • 상대 날짜를 서버 시간대로 계산
  • 물리 alias와 인증된 owner filter 주입
  • 허용 도구·중복 action·최대 4회 검사
  • 근거 정규화·소유권·인용 ID 검증
  • 제한된 대화 메모리 저장
현재 인용 검증의 경계인용 검증은 답변의 `[S1]`이 실제 근거 목록에 존재하고 현재 사용자 소유인지 확인한다. 문장 내용이 S1로 의미적 뒷받침되는지까지 판정하는 entailment 검사는 아니다.

05 / Conversation

멀티턴은 conversation_id와 구조화 메모리로 이어진다

첫 응답이 만든 ID를 다음 요청에 다시 보내면 MongoDB가 같은 소유자의 메모리만 로드한다. 다른 사용자가 같은 ID를 보내면 존재 여부를 노출하지 않고 거부한다.

Turn 01

일정 전체 조회

“이번 주 일정 뭐야?”

Calendar 근거 5건을 반환하고 현재 주제, 검색 기록, 근거와 이벤트 참조를 저장한다.

Turn 02

앞선 결과 후속 질문

“그중 첫 번째 일정의 상세 내용과 참석자를 알려줘”

동일한 conversation_id로 메모리를 로드하고 다시 routing → planner → judge → answer를 실행한다.

MongoDB에 저장되는 전체 메시지 기록과 구조화 메모리

messages ≤ 20turns ≤ 20cited_evidence ≤ 8entities ≤ 16current_topicprevious_event_referencesearch_history ≤ 16unresolved_information ≤ 8

STORE · 저장됨

최근 전체 메시지 기록과 turn 실행 정보, 인용 근거, 구조화된 주제·엔터티·이벤트 참조를 저장한다.

PROMPT · 현재 LLM에 보임

현재 네 의미 호출에는 전체 메시지 기록을 그대로 보내지 않는다. bounded entities, current topic, 필요한 previous event reference 등 제한된 구조화 메모리만 전달한다.

07 / Known boundaries

현재 구현이 하지 않는 것

구조를 이해하려면 성공 흐름뿐 아니라 현재 경계도 함께 봐야 한다. 아래 항목은 숨기지 않고 다음 개선 지점으로 남긴다.

01

전체 대화 원문 전달 아님

전체 메시지는 저장하지만 현재 LLM 호출에는 제한된 구조화 메모리만 전달한다.

02

인용 entailment 검사 없음

인용 ID와 소유권은 검증하지만 문장의 의미적 뒷받침 여부까지 재판정하지 않는다.

03

Free 모델 가용성 변동

OpenRouter free 라우팅은 모델 선택, 응답 시간, 구조화 출력 품질이 달라질 수 있다.

04

추가 검색은 추가 Judge 호출

초기 4회가 고정 상한은 아니다. 추가 도구 라운드마다 Judge 호출이 한 번씩 늘어난다.

05

오프라인 시나리오는 fixture

외부 서비스 없는 고정 시나리오는 테스트·데모용이며 실제 프로덕션 의미 경로가 아니다.

06

Chain-of-thought 비노출

구조화된 reason과 trace만 다루며 숨겨진 모델 추론 과정은 저장하거나 표시하지 않는다.
