# 그룹 주보 스튜디오

현재 레포에 **새 파일만 추가**한 로컬 웹 애플리케이션입니다. 기존 파일·실행 경로·의존성 파일은 변경하지 않습니다. 기존 모듈 import는 가능하지만 이 구현은 별도 패키지로 구성되어 기존 앱 초기화나 색인 작업을 실행하지 않습니다.

## 실행

레포 루트에서 기존 Python 환경을 사용할 때:

```bash
cd group_report_studio
../.venv/bin/python run.py
```

브라우저에서 http://127.0.0.1:8091 을 엽니다. 연결 설정이 없어도 화면과 목차·주보 저장을 확인할 수 있으며, 운영 데이터를 만들어 표시하지 않습니다.

별도 환경을 만들려면:

```bash
cd group_report_studio
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
cp .env.example .env
# .env에 OpenSearch와 사내 모델 연결값을 입력합니다.
.venv/bin/python run.py --env-file .env
```

기존 환경에 필요한 라이브러리가 없다면 **새 폴더의** requirements.txt를 설치하거나 별도 환경을 사용하세요. 루트 requirements.txt/pyproject.toml을 수정할 필요가 없습니다. 루트 `.env`는 자동으로 읽지 않습니다. 실제 키·암호를 소스 코드에 적지 않습니다.

## 연결 설정

| 설정 | 설명 |
|---|---|
| `GR_OPENSEARCH_URL` | 기존 OpenSearch의 주소와 포트 |
| `GR_OPENSEARCH_INDEX` | 기본 `weekly_mail` |
| `GR_OPENSEARCH_USER`, `GR_OPENSEARCH_PASSWORD` | 기존 읽기 권한 계정. 인증이 없으면 비워 둠 |
| `GR_OPENSEARCH_VERIFY_TLS` | 기본 true. 서비스 인증서 검증 여부 |
| `GR_OPENSEARCH_KEYWORD_SUFFIX` | week/type/mail_type이 keyword면 빈 문자열. text+keyword 하위 필드면 `.keyword` |
| `GR_LLM_BASE_URL` | 사내 OpenAI 호환 Chat Completions API 주소. `/v1` 같은 버전 경로까지 포함 |
| `GR_LLM_MODEL` | 사용할 모델 이름 |
| `GR_LLM_API_KEY` | 인증 필요 시 설정 |
| `GR_DATA_DIR` | 주보·버전·근거·작업 기록 저장 위치. 기본 새 폴더의 `.local/` |

모델 호출은 지정한 `GR_LLM_BASE_URL`로 원문 일부·참고 주보·수정 지시를 전달합니다. 별도 임베딩 API나 외부 검색을 사용하지 않습니다. 준비 상태는 필수 설정 존재 여부이며, 실제 연결 성공을 의미하지 않습니다.

OpenSearch에는 다음 조건의 전체 문서를 조회합니다.

```json
{"week":"2026-01","mail_type":"weekly_report","type":"original_part"}
```

`embedding`을 읽지 않고, 메일 본문과 메타데이터만 사용합니다. 검색/scroll 및 scroll 해제만 호출하며 문서 추가·수정·삭제, 인덱스 생성, refresh는 하지 않습니다. 조회 도중 timeout/샤드 실패/조회 건수 불일치가 있으면 일부 자료로 성공 처리하지 않습니다. `html_path`는 메타데이터이며 로컬 경로를 읽거나 실행하지 않습니다.

## 사용 흐름

1. **새 주보**에서 ISO 주차·제목·포함되어야 할 팀을 입력합니다.
2. 기본 0~5번 목차를 사용하거나 소주제를 추가·삭제·이동하고 작성 지침을 고칩니다. 자주 쓰는 목차는 별도 양식으로 저장합니다.
3. 직전 1주·2주의 **그룹 전체 주보**를 DOCX/TXT/MD 파일 또는 본문으로 등록하고 각각의 주차를 지정합니다. 참고 자료 없이도 작성할 수 있지만 보고서에 경고가 표시됩니다.
4. 초안 생성 진행 상태를 확인합니다. 큰 원문은 분할 처리하고 원문 인용·사실·소주제 결과를 단계별로 저장합니다. 실패/취소 시 저장된 단계부터 재시도할 수 있습니다.
5. 문서에서 소주제를 선택하고 오른쪽 대화에 수정 요청을 적습니다. 선택하지 않으면 전체 문서를 대상으로 해석합니다.
6. 근거·경고·버전 기록을 확인합니다. 복원은 과거 버전을 삭제하지 않고 새 버전을 만듭니다.
7. **확정 → Word 받기**로 해당 버전의 DOCX를 내려받습니다. 이후 수정하면 새 초안이 되며 과거 확정본은 보존됩니다.

목차 변경은 대화로도 요청할 수 있습니다. 제목 변경·순서 변경은 기존 본문을 유지합니다. 항목 추가나 작성 지침 변경은 필요한 항목만 다시 작성합니다. 소주제 ID를 유지해 인용과 수정 이력을 연결합니다. 자연어로 양식을 바꾼 후 **현재 목차 저장**을 누르면 다음 주보에서 해당 양식을 선택할 수 있습니다.

예시:

- “Spica의 제품별 CUM0를 표로 바꾸고 개선 내용은 한 문장으로 줄여줘.”
- “이 항목 제목만 Spica 현황으로 바꿔줘.”
- “HBM4E의 일정 지연 원인을 원문 근거로 보강해줘.”
- “고객품질을 공정품질 앞으로 옮겨줘.” (전체 문서 선택)

## 파일 구조

```text
group_report_studio/
  run.py                  로컬 전용 실행 진입점
  requirements.txt        새 기능의 의존성만 정의
  .env.example            연결 설정 예시
  studio/
    api.py                주보·작업·양식·다운로드 API
    models.py             가변 목차·문서·모델 응답 구조
    config.py             독립 환경 설정
    source.py             OpenSearch 전체 조회·원문 분할·수집 점검
    llm.py                호환 모델 API·입력 한도·HTTP 재시도
    prompts.py            추출·작성·편집·검증 지시
    harness.py            생성·편집·부분 저장·재개 실행 흐름
    store.py              SQLite 버전·근거·작업 저장
    documents.py          DOCX 출력·이전 주보 본문 읽기
    static/               별도 빌드가 필요 없는 웹 화면
  tests/                  원문·생성·편집·버전·API·Word 검증
  docs/implementation.md   구현 범위와 API 계약
```

실행 상태는 명시적 Python 단계로 제어합니다. LangGraph나 기존 RAG 대화 상태를 가져오지 않아 기존 시스템과 의존성이 결합되지 않습니다. 나중에 실행 엔진을 교체해도 문서 버전 저장소와 API 계약은 유지할 수 있습니다.

## 입력량과 근거 처리

- 한 번의 모델 입력은 프롬프트·JSON 구조를 포함한 UTF-8 바이트 상한으로 제한합니다. 기본 40,000바이트, 원문 조각 10,000바이트, 모델 출력 6,000토큰입니다. 실제 모델의 컨텍스트에 맞춰 세 값을 조정해야 합니다. 모든 토크나이저의 정확한 토큰 수를 계산하는 방식은 아닙니다.
- 전체 원문을 먼저 수집하고 각 조각에서 사실을 추출합니다. 조회 상위 몇 건만 선택하지 않습니다. 추출에서 모델이 누락한 사실까지 완전성을 보장하지는 않습니다.
- quote는 원문에 실제 존재해야 합니다. 사실의 저장 텍스트는 원문 quote를 사용합니다. 작성 블록은 근거 ID 검사와 모델의 의미 검증을 모두 거칩니다.
- 큰 소주제는 작은 묶음으로 작성하고 검증된 초안을 합칩니다. 합친 결과도 검증합니다. 더 이상 안전하게 한 요청에 합칠 수 없는 내용은 여러 블록으로 유지합니다. 이 경우 묶음 사이의 유사한 표현이 남을 수 있습니다.
- 핵심 이벤트는 검증된 후보에서 최대 3건을 단계적으로 선정합니다. 분할 후보 선정은 전역 최적 순위를 보장하지 않으므로 사용자가 최종 검토합니다.
- 이전 주보는 과거 주차로 표시된 근거로 분리하고 표현 규칙을 별도로 추출합니다. 이전 Word의 페이지 배치나 회사 로고를 복제하는 기능은 아닙니다.
- 수정은 선택한 항목의 현재 블록과 관련 근거를 사용합니다. 다른 항목이 같은 근거를 인용하면 재확인 경고를 남깁니다. 다른 항목을 자동으로 다시 쓰지는 않습니다.
- 사용자가 직접 제공한 정정 문구는 실제 요청의 연속된 문자열인지 검사하고 원 요청을 별도 출처로 남깁니다. 원문 수치는 바뀌지 않습니다.
- 모델의 의미 검증은 자동 보조 검사이며, 수치·분모·조건의 정확성을 완전히 보장하지 않습니다. 충돌·미보고 경고가 있어도 사용자가 검토 후 확정할 수 있습니다.

## Word와 운영 범위

현재 DOCX는 기본 보고서 양식입니다. 회사 Word 원본 양식은 아직 제공되지 않아 `documents.py`의 출력 스타일에서 나중에 반영합니다. 웹에 저장한 문단·표를 그대로 출력하며 Word 생성 때 모델을 다시 호출하지 않습니다. 한국어 표시를 위해 서버와 Word 사용 환경에 한국어 글꼴이 필요합니다.

로컬 단일 사용자·단일 서버 프로세스용입니다. 기본 바인딩은 127.0.0.1이며 인터넷에 공개하지 않습니다. 사내 공용 서비스로 배포하려면 인증·문서 접근 권한·배포용 워커 관리를 추가해야 합니다. 실행 체크포인트에는 원문이 포함되므로 `.local/`을 회사 자료와 같은 기준으로 관리하세요.

취소는 실행 중인 모델/검색 HTTP 요청이 끝난 다음 단계에서 반영됩니다. 서버를 다시 시작하면 실행 중이던 작업은 재시도 가능한 실패 상태로 전환됩니다. 이미 저장된 주보 버전은 재시도에서 중복 생성되지 않도록 실행 ID를 확인합니다. 유효성 검사에 실패한 모델 응답은 캐시하지 않습니다.

## 검증

```bash
cd group_report_studio
../.venv/bin/python -m unittest discover -s tests -v
node --check studio/static/app.js
```

테스트의 OpenSearch와 모델은 명시적인 대역이며 운영 인덱스에 쓰지 않습니다. 실제 인덱스·모델을 통한 생성 품질은 연결 설정 후 해당 주차의 자료로 별도 확인해야 합니다. 회사 원본 양식 적용과 실제 모델 품질 검증은 제공된 파일·설정이 있어야 수행할 수 있습니다.
