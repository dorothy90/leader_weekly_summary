# 그룹 주보 더미 입력 세트

모든 팀명·지표·활동은 가상 테스트 데이터입니다.

- 이번 주: ISO 2026-37 (2026-09-07~09-13)
- 참고 그룹 주보: 2026-35 (08-24~08-30), 2026-36 (08-31~09-06)
- 팀별 주보: 36개 팀 × 2조각 = 72개 원문
- OpenSearch: 기존 `weekly_mail`, 실제 `qwen/qwen3-embedding-8b` 4096차원 임베딩
- 문서 ID: `demo_gr_2026_37_team_01_part_0` 형태. 기존 ID를 덮어쓰지 않는 create 방식.

## 웹에서 사용

http://127.0.0.1:8091/ 에서 `[더미] 그룹 주간보고 2026-37`을 선택합니다.
이전 두 주 참고 주보와 36개 팀 목록이 입력되어 있습니다. `초안 생성`으로 생성 작업을 시작합니다.
현재 데이터 준비·색인·업로드 처리를 검증했으며 LLM의 전체 초안 생성은 아직 실행하지 않았습니다.

직접 입력하려면 새 주보의 대상 주차를 `2026-37`로 설정하고,
이 폴더의 `그룹주보_2026-36_더미.docx`를 직전 1주, `그룹주보_2026-35_더미.docx`를 직전 2주에 업로드합니다.
`teams.txt` 내용을 대상 팀 목록에 붙여 넣습니다.

## 파일

- `그룹주보_2026-35_더미.docx`, `그룹주보_2026-36_더미.docx`: 기본 20개 소주제, 모든 수치 비교를 문장과 글머리표로 작성
- `teams/`: 각 팀의 TXT 원문과 body.html
- `team_documents.json`: 임베딩을 제외한 원본 색인 데이터
- `create_report.json`: 두 참고 자료를 포함한 웹 보고서 생성 입력
- `index_result.json`: 색인 결과와 72개 문서 ID
- `validation.json`: 실제 앱 조회 및 업로드 검증 결과
- `web_report.json`: 준비된 웹 보고서 ID

## 재실행

레포 루트에서 실행합니다. 기존 `.env`를 읽기만 하며 변경하지 않습니다.

```bash
.venv/bin/python group_report_studio/demo_2026_37/seed.py
.venv/bin/python group_report_studio/demo_2026_37/run_demo.py
```

`seed.py`는 동일한 ID·내용이면 건너뛰고, 내용이 다르면 덮어쓰지 않고 중단합니다.
`run_demo.py`는 8091 포트를 사용하므로 기존 작업실 실행을 종료한 뒤 실행합니다.
임베딩 캐시는 별도 `.local/demo_embeddings/`에 저장됩니다.
숫자 비교와 추적 시험을 위해 개선, 악화 signal, 미완료 검증 및 여러 팀이 공유하는 고객 이슈를 포함했습니다.
