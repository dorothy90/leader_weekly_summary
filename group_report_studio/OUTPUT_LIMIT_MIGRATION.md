# 출력 토큰 초과 대응 이식 지침

## 목적과 범위

사내에서 출력 한도를 6,000에서 12,000으로 높여도 `finish_reason=length` 오류가 발생하는 경우를 처리한다. 이 변경은 출력 초과를 재현하는 모의 모델로 검증했다. 사내 모델에서의 실제 성공 여부는 사내에서 확인해야 한다.

이 문서와 **같은 버전의 코드 파일**을 함께 반입한다. 문서만 보고 코드를 새로 구현하지 않는다. 기존 설치 절차는 [MIGRATION_GUIDE.md](MIGRATION_GUIDE.md)를 따른다.

## 1. 변경 파일: 이 목록만 적용

실행 코드:

- `studio/llm.py`
- `studio/harness.py`

검증 코드:

- `tests/test_output_limit.py` — 신규 파일
- `tests/test_harness.py`
- `tests/test_extraction_retry.py`
- `tests/test_regressions.py`

설명서:

- `OUTPUT_LIMIT_MIGRATION.md` — 이 파일

경로는 모두 `group_report_studio/` 기준이다. `.env`, `studio/config.py`, 회사 모델명, 인증정보, OpenSearch 설정, 로컬 DB를 덮어쓰지 않는다. 사내에서 지정한 12,000토큰 설정은 그대로 유지할 수 있다. 이번 변경은 토큰 기본값을 올리는 변경이 아니다.

## 2. 적용 방식 선택

### 사내 파일에 별도 수정이 없는 경우

1. 실행 중인 작업이 끝난 뒤 서버를 종료한다.
2. 현재 코드와 데이터 디렉터리를 사내 승인 경로에 백업한다. SQLite 백업은 서버 종료 후 수행한다.
3. 위 목록의 파일을 이 문서와 함께 전달된 파일로 교체한다.
4. 5절의 검증을 실행한다.
5. 기존 사내 실행 명령과 환경 설정으로 서버를 다시 시작한다.

### 사내 모델 연결 등을 이미 수정한 경우

파일 전체를 덮어쓰지 말고 아래 변경 사항을 병합한다. 특히 `llm.py`에 구현한 회사 전용 헤더, 인증, URL, 요청 형식은 유지한다.

`studio/llm.py`:

1. `LLMError`를 상속하는 `LLMOutputLimitError`를 추가한다.
2. `finish_reason == 'length'`에서 일반 `LLMError` 대신 이 예외를 발생시킨다.
3. 이 예외를 JSON 형식 오류로 변환하지 않는다. 기존 `isinstance(exc, LLMError)` 처리에서 그대로 전달된다.
4. 해당 오류 로그에는 단계, 입력 JSON 바이트 수, 요청 출력 한도만 남긴다. 본문과 인증정보는 기록하지 않는다.

예외 정의:

```python
class LLMOutputLimitError(LLMError):
    pass
```

`studio/harness.py`:

1. `LLMOutputLimitError`를 import한다.
2. `Harness.call`의 마지막 인자로 `depth=0`을 추가한다.
3. 모델 호출 자체에서 발생한 출력 초과와 `validate(result)` 내부 검증 호출에서 발생한 출력 초과를 모두 `recover_limit()`으로 전달한다.
4. `recover_limit()`은 `write`의 `facts`, `extract_lines`의 `numbered_lines`를 반으로 나눠 같은 `call`을 재귀 호출한다. 최대 분할 깊이는 6이다.
5. `extract_lines` 분할 시 줄 번호를 다시 매기지 않는다. 처음 입력한 줄 목록을 `context_lines`로 유지해 제품·조건·기간 문맥을 제공한다. 기존 `convert()`는 전체 원문 줄 목록을 기준으로 인용문을 복원한다.
6. 자식 호출에도 기존 `validate` 함수를 전달한다. 분할했다는 이유로 근거 검증을 생략하지 않는다.
7. 성공한 자식 결과는 기존 `checkpoint()` 경로에 저장한다. 부모 실패 시에도 이미 성공한 자식 결과를 재사용한다.
8. `Harness.extract()`는 처음부터 `extract_by_lines()`를 사용한다. 원문 인용문을 모델에게 다시 작성하게 하지 않는다.
9. `write_section()`에서 `while len(sections)>1`로 모델을 호출하던 통합 루프를 제거하고, 검증된 블록과 경고를 순서대로 합친다. 핵심 이벤트의 기존 ID/인덱스 선택 흐름은 유지한다.

이 절의 설명은 검토용이다. 실제 함수 구현은 동봉된 `harness.py`와 비교하여 적용한다.

## 3. 단계별 동작과 한계

- 원문 추출 `extract_lines`: 출력이 잘리면 담당 줄 목록을 절반씩 줄인다. 인용문은 코드가 원문에서 복원한다. 문맥 줄은 모델에게 제공하지만, 모델의 의미 이해나 사실 누락까지 보장하지 않는다.
- 본문 생성 `write`: 사실 목록을 절반씩 나눠 작성·검증한다. 검증기에서 출력 초과가 나도 같은 분할 경로를 사용한다.
- 본문 조립: 모델 호출 없이 검증된 블록을 연결한다. 서로 다른 묶음 사이에 유사한 표현이 남을 수 있다.
- 사실 한 건 또는 분할 깊이 6에 도달한 본문 생성: 인용 ID와 경고가 있는 원문 발췌로 전환한다. 잘린 초안을 성공 처리하지 않는다.
- 최소 단위에서도 실패한 원문 추출: 명시적인 오류로 중단하며 완료된 결과를 보존한다. 사실을 임의로 생략해 성공 처리하지 않는다.
- 대화 편집 `edit`, 편집 계획, 참고 문체 추출, 핵심 이벤트 선택: 이번 자동 분할 대상이 아니다. 출력 초과 시 중단한다. 대화 편집을 임의로 분할하면 전체 수정 의도가 달라질 수 있어 기존 문서를 보존한다.
- 입력 한도 초과, 인증 실패, HTTP 오류: 출력 초과와 별개의 오류다. 이 변경으로 해결되지 않는다.

분할 시 문맥을 유지하므로 입력 바이트가 충분히 줄어들지 않을 수 있다. 이번 변경의 목적은 **한 번에 요구하는 출력량을 줄이는 것**이다. 입력 한도에 걸리면 원문 조각 크기와 프롬프트 크기를 별도로 조정해야 한다.

## 4. 재시작과 기존 작업

일반 실행 예시:

```bash
cd group_report_studio
.venv/bin/python run.py --env-file .env --port 8091
```

사내에서 사용하는 가상환경 경로가 다르면 Python 실행 경로만 바꾼다. `run_demo.py`는 출력 한도 환경변수를 전달하지 않으므로 운영 실행 진입점으로 사용하지 않는다.

실패한 기존 작업은 화면의 재시도로 이어갈 수 있다. 추출 방식과 프롬프트가 바뀌었기 때문에 최초 재시도 때 기존 문자열 인용 추출 캐시 대신 줄 번호 추출을 다시 실행할 수 있다. DB 파일을 삭제할 필요는 없다. 이미 생성 완료된 보고서를 이 변경으로 다시 시험하려면 새 보고서를 만들어 생성한다.

## 5. 검증 명령과 합격 기준

`group_report_studio/`에서 실행한다. 아래 테스트는 외부 모델이나 OpenSearch에 접속하지 않는다.

```bash
.venv/bin/python -m unittest discover -s tests -p 'test_output_limit.py' -v
.venv/bin/python -m unittest discover -s tests -q
```

이 버전의 예상 결과는 출력 초과 테스트 4개, 전체 테스트 41개 통과다. 새 출력 초과 테스트는 다음 사항을 확인한다.

1. 서버의 `length` 응답이 전용 예외로 전달된다.
2. 사실 4건을 1건씩 나눠도 모든 문장과 인용 ID가 보존되고, 재호출 시 캐시를 재사용한다.
3. 줄 번호 추출을 분할해도 전체 줄 번호와 문맥 목록을 유지한다.
4. 더 나눌 수 없는 본문은 원문 발췌로 전환하고, 대화 편집은 실패 처리한다.

사내 실데이터 검증:

- 이전에 출력 한도 오류가 났던 주차로 시험한다.
- 서버 로그의 `Model output limit`에서 단계명을 확인한다.
- 생성 완료 또는 명확한 최소 단위 오류가 나오는지 확인한다.
- 수율 값·제품명·집계기간·완료/미완료 상태를 원문과 대조한다.
- 원문 발췌 경고가 있는 항목을 사람이 검토한다.
- 결과가 문장·글머리표로 표시되고 Word에서도 표가 없는지 확인한다.

실제 사내 자료나 로그를 외부로 반출할 필요는 없다.

```text
9. 적용 파일, 테스트 결과, 사내 실데이터 확인 결과를 보고한다.

금지 사항:

- .env, 인증정보, OpenSearch 인덱스, 운영 DB를 변경하지 않는다.

```
