# Word에서 기본 작성 프롬프트 만들기

## 사용 순서

1. 서버를 재시작하고 웹 화면을 새로고침합니다.
2. **새 주보 → 작성 프롬프트**에서 대표 `.docx` 주보를 선택합니다.
3. **Word에서 목차·규칙 추출**을 누릅니다. 설정된 사내 모델이 목차, 소주제별 지침, 공통 작성 프롬프트를 만듭니다.
4. 목차 편집과 공통 작성 규칙을 확인·수정합니다. 과거 주차의 실적·수치·사건이 포함되면 제거하세요. 추출 결과는 아직 저장되지 않은 초안입니다.
5. **목차·규칙을 기본 양식으로 저장**을 누릅니다. 이후 새 주보는 자동으로 이 양식을 사용합니다. 이전 2주 주보는 업로드하지 않아도 됩니다.
6. 이번 주 주보를 만들면 OpenSearch 원문을 근거로 저장된 양식에 맞춰 작성합니다. 다른 이름의 양식으로 남기려면 기존 양식 저장 체크박스를 사용할 수도 있습니다.

Word의 본문은 양식 추출을 위한 모델 입력으로만 사용됩니다. 이번 주 근거 자료나 이전 주차 참고 자료로 자동 등록되지 않습니다. 저장된 기본 양식은 서버 재시작 후에도 유지되고, 변경해도 이미 만든 주보의 양식은 바뀌지 않습니다.

## 사내 이식 범위

모든 변경은 `group_report_studio` 안에 있습니다. 원래 수집·색인 파일이나 OpenSearch 매핑은 수정하지 않습니다. 추가 외부 의존성은 없습니다.

다음 파일을 함께 반영하세요.

- `studio/word_template.py`: 신규. DOCX 본문 → 모델 호출 → Template 검증.
- `studio/models.py`: Template에 선택 필드 `writing_prompt` 추가, 최대 6000자. 기존 자료는 빈 문자열로 호환.
- `studio/store.py`: preferences 테이블과 기본 양식 읽기/저장. 서버 시작 시 테이블을 자동 생성하므로 DB를 삭제하거나 초기화하지 마세요.
- `studio/api.py`: 양식 추출·기본 양식 저장 API, config에서 저장된 기본 양식 반환.
- `studio/harness.py`: 생성·문장 편집에 writing_prompt 전달. 대화 목차 수정 중에는 저장된 공통 규칙을 보존.
- `studio/prompts.py`: 근거/표 금지 규칙을 유지하며 사용자 수정 요청 → 소주제 지침 → 공통 프롬프트 → 이전 문서 문체 순으로 표현 규칙 적용.
- `studio/static/index.html`, `studio/static/app.js`: 업로드, 추출, 검토·수정, 기본 저장 화면.
- `tests/test_word_template.py`: 신규 통합 테스트.

API는 다음과 같습니다.

- `POST /api/templates/from-word`: `{name, content_base64}` → `{name, sections, writing_prompt}`. 자동 저장하지 않습니다. OpenSearch 연결 없이 모델 연결만 있으면 추출 가능합니다.
- `POST /api/templates/default`: 검토한 Template 객체 → 저장된 Template 객체.
- `GET /api/config`: `default_template`에 서버에 저장한 기본 양식을 포함합니다.
- 기존 `POST /api/templates`, `POST /api/reports`도 template.writing_prompt를 저장합니다.

프롬프트 추출에는 기존 `GR_LLM_BASE_URL`, `GR_LLM_MODEL`, `GR_LLM_API_KEY` 설정을 사용합니다. 회사 자료를 처리할 때 이 주소가 사내 모델을 가리키는지 확인하세요.

## 확인 방법과 한계

### 중점 추진과제 자동 선정

`중점 추진과제` 대주제의 하위 항목은 고정 목록이 아닙니다. Word 추출 결과, 양식 저장/불러오기, 신규 주보 생성에서 기존 PSDI/WLQM 등의 예시 항목을 `금주 중점 추진과제 자동 선정` 규칙으로 통합합니다. 띄어쓰기와 대주제 앞 번호가 있어도 인식합니다. 해당 대주제가 없는 양식에는 자동으로 추가하지 않습니다.

생성 시 모든 팀의 금주 추출 근거(미분류 근거 포함)를 검토하여 영향·시급성·진척·장애 요인 기준으로 최대 3개 과제를 고릅니다. 긴 입력은 묶음별 후보 선정 후 재선정하므로 한 번의 요청에 전체 원문을 넣지 않습니다. 과거 주보는 이 선정의 근거에서 제외합니다. 최종 과제명으로 소주제를 만들고 선정 근거를 연결하여 기존 본문 검증을 거칩니다. 적합한 과제가 없으면 미보고로 표시합니다. 후보 축약 중 일부 관련 근거는 제외될 수 있으며 선정 품질은 모델 판단에 좌우됩니다.

추가 이식 파일: `studio/priority.py`, `tests/test_priority.py`. 또한 `models.py`, `api.py`, `word_template.py`, `harness.py` 변경을 함께 반영하세요. 이미 저장된 양식도 읽을 때 변환하므로 DB를 초기화할 필요가 없습니다. 기존 완성 문서는 유지하고 재생성 시 새 규칙을 적용합니다. 생성된 과제 목차를 양식으로 저장해도 다음 주에는 다시 선정합니다.

프로젝트 가상환경에서 `group_report_studio`로 이동해 `python -m unittest discover -s tests -q`를 실행하세요. 테스트는 임시 DB, 메모리에서 만든 DOCX, 가짜 모델·검색 데이터를 사용합니다.

화면에서는 추출 후 수동 수정 → 기본 저장 → 새 주보 다시 열기 → 이전 주보 없이 생성 순서로 확인하세요. 잘못된 파일, 빈 DOCX, 입력 한도 초과 시 기존 입력과 기본 양식이 유지되는지도 확인하세요.

- DOCX의 텍스트를 분석합니다. `.doc`, 스캔/이미지 본문 OCR, 글꼴·로고·페이지 배치 복제는 지원하지 않습니다.
- 원문 표는 읽을 수 있지만 새 주보는 문장·글머리표만 사용합니다.
- `GR_MAX_INPUT_BYTES`를 넘는 문서는 조용히 잘라내지 않고 오류로 안내합니다. 목차와 대표 문단을 남긴 짧은 DOCX로 다시 시도하세요.
- 문체와 분량 규칙은 모델에 전달되는 지침입니다. 최종 글자 수를 강제로 자르는 기능은 아니며, 원문이 여러 묶음으로 나뉘면 합친 결과의 분량이 상한을 넘을 수 있습니다.
- 모델이 추출한 규칙의 정확성은 저장 전 확인이 필요합니다. 실제 과거 수치 제거는 모델 지시이며 자동으로 완벽히 보장하지 않습니다.
- 이 추출 요청은 주보 생성 job과 별개의 동기 API입니다. 기존 job 호출 기록 화면에는 나타나지 않습니다. 실패 메시지는 추출 버튼 아래에 표시됩니다.
