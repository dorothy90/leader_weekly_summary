# 최종 형식·분량 검토 단계

## 동작

생성 또는 본문 편집을 마친 뒤, 버전 저장 직전에 `review_final`을 실행합니다. 기존 원문 근거 검증을 대체하지 않습니다. 본문이 바뀌지 않는 확인 질문에는 실행하지 않습니다. 확정 시에는 마지막 저장 버전의 검토 결과를 유지합니다.

1. 코드로 현재 양식의 소주제 순서·제목, 표 여부, 인식 가능한 명시적 분량 규칙을 확인합니다.
2. 이전 그룹 주보가 있으면 전체 본문 및 제목이 식별된 소주제의 분량을 비교합니다. 중점 추진과제의 과거 소주제 목록을 이번 주에 강제하지 않습니다.
3. 모델이 저장 규칙과 기존 `reference_style` 분석 결과를 사용해 문체·글머리표·단위 표기·서론·중복 설명을 검사합니다. 4개 소주제 이하, 입력 크기 기준으로 묶습니다. 과거 원문 전체를 매번 다시 보내지 않습니다.
4. 문제가 있는 소주제 중 최대 3개에 대해 각각 1회 보정합니다. 짧은 문서를 과거 분량에 맞추려고 내용을 지어내지는 않습니다.
5. 기존 숫자 토큰과 인용 ID 보존을 코드로 검사하고, 모델의 양방향 의미 보존 검사와 원문 근거 검증을 통과한 보정만 적용합니다. 보정 후 형식·분량을 다시 검사합니다.
6. 미해결 문제나 검토 모델 실패는 `확인 필요`로 표시합니다. 검토 문제만으로 작성된 초안을 폐기하지 않습니다. 취소 요청은 기존대로 처리합니다.

편집 시 자동 보정 범위는 그 요청으로 바뀐 소주제로 제한됩니다. 최신 사용자 요청은 문체 검토와 보정 입력에 포함됩니다. 코드 검사는 저장 규칙을 검사하므로 사용자가 임시로 규칙과 다른 분량을 요청한 경우 확인 필요가 남을 수 있습니다.

## 기준과 한계

- `GR_FORMAT_TOLERANCE_PERCENT=20`: 이전 주보 평균 대비 기본 ±20%. 0~100 범위입니다. 이전 주보 1개만 있으면 그 파일을 기준으로 비교합니다.
- `GR_FORMAT_AUTO_REPAIR=true`: 자동 보정 사용. `false`면 비교와 검토 결과만 표시합니다.
- 저장 규칙에 식별 가능한 명시적 분량 제한이 있으면 과거 분량 기준보다 우선합니다. 예: `문장당 150자를 초과하지 않는다`, `소주제당 2문장 이내`, `전체 3000자 이하`.
- 전체/소주제 글자 수는 공백을 제외합니다. 문장 길이는 공백을 포함합니다. 문장 수는 줄바꿈 및 문장부호 뒤 공백을 기준으로 센 근사치입니다.
- 과거 DOCX는 추출된 텍스트를 사용하므로 전체 길이에 제목·날짜 등이 일부 포함될 수 있습니다. UI에 근사 비교임을 표시합니다. 소주제는 인식 가능한 독립 제목에만 연결하며, 매칭되지 않으면 비교 없음으로 표시합니다.
- 한글 수사·복잡한 분량 조건을 모두 해석하는 범용 규칙 파서는 아닙니다. 코드가 인식하지 못하는 자연어 분량 조건은 수동 확인이 필요합니다.
- 글꼴·여백·페이지 수·Word 시각적 배치는 검사하지 않습니다. 수치 보존 코드는 보수적 보조 장치이며 문맥·의미 보존은 모델 판단도 사용합니다.
- 최종 검토에도 모델 호출이 추가됩니다. 재검토는 보정한 부분만 수행하고, 보정은 최대 3개로 제한합니다. ChatModel 자체의 HTTP/JSON 형식 재시도는 기존 정책을 유지합니다.

## 사내 이식

추가 파일은 `studio/format_review.py`, `tests/test_format_review.py`입니다. 다음 변경도 함께 반영하세요.

- `studio/harness.py`: 생성·편집 결과 저장 전 검토 단계 호출.
- `studio/config.py`, `.env.example`, `demo_2026_37/run_demo.py`: 허용 범위와 자동 보정 설정.
- `studio/static/index.html`, `studio/static/app.js`: 본문 위 형식·분량 검토 패널.
- `tests/test_harness.py`: 기존 테스트 모델에 최종 문체 검사 응답 추가.

기존 DB JSON에 `format_review` 필드를 저장하므로 DB 초기화나 스키마 이식은 필요 없습니다. 이전 완성 문서에는 결과가 없으며 새 생성·편집부터 추가됩니다. 반영 후 서버를 재시작하고 브라우저를 새로고침하세요.

API `GET /api/reports/{id}`의 `format_review`에서 현재/과거 글자 수, 소주제별 통계, 최초 문제 목록, 최종 문제 목록, 보정 항목과 보정 실패 안내를 확인할 수 있습니다. `GET /api/jobs/{id}`의 metrics에는 `final_style`, `format_repair`, `format_preservation` 호출 통계가 포함됩니다. 디버그 활성화 시 기존 호출 기록에도 남습니다.

## 검증

`group_report_studio`에서 프로젝트 가상환경의 `python -m unittest discover -s tests -q`를 실행합니다. 테스트는 실제 사내 자료나 외부 모델을 사용하지 않습니다.

이전 자료 없음, 명시적 규칙 우선, 동적 과제 제목 허용, 표/목차 검사, 수치 누락 보정 거부, 1회 보정 후 근거 검증, 모델 실패 시 초안 보존, 선택 범위 외 수정 방지를 포함합니다. 사내 모델로는 실제 샘플을 사용해 통과/확인 필요 결과와 추가 지연 시간을 확인하세요.
