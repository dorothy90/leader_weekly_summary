# 주보 생성 시간 개선

이번 변경은 원문 검토·소주제 작성 병렬 실행, 묶음 검증, 호출 통계에 한정합니다.

## 설정

`GR_WORKERS=2`: 원문 조각 검토 또는 소주제 작성을 최대 2개씩 실행합니다. 허용 범위는 1~4입니다. 서버 포화나 429 응답이 늘면 1로 낮추세요.

`GR_VERIFY_BATCH_SIZE=4`: 문단 4개를 한 번에 검증합니다. 허용 범위는 1~5입니다. 입력이 크면 더 작게 분할합니다. 묶음 검증 부정 판정이나 응답 형식/출력 길이 오류는 개별 검증으로 전환합니다. 개별 검증까지 실패한 주장은 통과시키지 않습니다. 각 문단 자신의 인용 근거로만 검증하도록 지시합니다.

`1`, `1`로 설정하면 순차 작업과 문단별 검증을 사용할 수 있습니다. 별도 의존성이나 OpenSearch 변경은 없습니다. 설정 후 서버를 재시작하세요. demo_2026_37/run_demo.py 실행 경로에도 이 두 설정을 반영했습니다.

## 변경 파일

- studio/config.py, .env.example: 두 설정 추가.
- studio/harness.py: 제한된 병렬 작업, 묶음 검증, 호출 시간 측정.
- studio/store.py: 병렬 캐시 저장과 통계 갱신을 SQLite 트랜잭션 안에서 병합. 기존 JSON DB를 그대로 사용합니다.
- studio/prompts.py: 묶음 내 문단별 인용 독립 검증 규칙.
- studio/api.py: GET /api/jobs/{job_id}에 metrics 추가.
- demo_2026_37/run_demo.py: 실행 설정 전달.
- tests/test_performance.py: 호출 수, 실패 검증, 동시 실행 제한, 병렬 저장 검증.

## 시간 확인

`GET /api/jobs/{작업ID}`의 metrics는 단계별로 calls, seconds, failures, retries를 제공합니다. 원문 검토는 extract_candidates, 작성은 write, 검증은 verify입니다. 통계에 프롬프트나 원문 내용은 없습니다.

- calls: 실제 ChatModel.complete 호출 수. 캐시 적중은 제외합니다.
- seconds: 해당 호출들의 누적 소요 초. 모델 클라이언트 내부 재시도 대기 시간도 포함합니다. 병렬 호출 시간이 합산되므로 전체 작업 경과 시간과 다릅니다.
- failures: 모델 호출/응답 스키마 검증에서 예외가 난 횟수. supported=false 판정은 이 값에 포함되지 않습니다.
- retries: 하네스의 검증 실패 후 재작성/재추출 호출 수. 모델 클라이언트 내부 HTTP 재시도 횟수와는 다릅니다.

기존 작업은 metrics가 없을 수 있습니다. 새 작업부터 측정하며 재시도하면 누적됩니다. 비교 시 동일한 자료의 새 작업을 사용하세요. 실제 시간 감소율은 사내 모델 서버의 동시 처리 능력과 검증 실패율에 달려 있습니다.

## 적용 범위와 검증

`python -m unittest discover -s tests -q`로 검증합니다. 가짜 모델에서 8문단 검증이 8회에서 2회로 감소하며, 잘못된 주장은 개별 검증에서 거부되는지 확인합니다. 동시 실행이 최대 2개인지, 완료 순서가 달라도 결과 순서와 캐시가 보존되는지도 검사합니다.

실패한 본문은 기존 재작성 흐름을 사용합니다. 실패 문단만 따로 재작성하는 기능, 다른 작업 사이의 캐시 공유, 핵심 이벤트의 검증된 본문 재사용, 문서 전체 분량 강제 제한은 이번 변경에 포함하지 않습니다. 기존 작업 캐시와 취소·재시도 동작은 유지하며 취소 시 이미 진행 중인 모델 요청은 응답이 올 때까지 기다릴 수 있습니다.
